Theoretical context

A graph stored as adjacency lists needs O(V + E) space for V variables and E interference edges. The full allocation pipeline also stores TAC instructions, CFG information, and live sets. Coloring the graph optimally is NP-complete; the Chaitin–Briggs heuristic usually avoids exhaustive search. The bounded exact fallback used for small hard graphs can have exponential worst-case behavior.

For an empirical complexity argument, compare the two input-size charts, repeat measurements, and report the test environment. Operating system scheduling and Python allocation overhead create natural variation.

Start here: a four-step walkthrough

  1. Load TAC. Select Simple or paste your own program into the source editor.
  2. Set K. K is the maximum number of physical registers available, numbered R0 through R(K−1).
  3. Run analysis. The backend builds a CFG, computes liveness, constructs an interference graph and assigns colors. Under pressure, it inserts spill loads/stores and retries.
  4. Compare. Change K, switch between iterations and use the Complexity lab to collect experimental measurements.
01 · CONTROL FLOW

What is a basic block?

A basic block is a sequence of instructions with a single entry and exit. The CFG shows which block can execute next, including branches and loops.

02 · DATA FLOW

Why is liveness important?

A variable is live when its current value may still be read. Two values live at the same time often need different physical registers. Liveness depends on the program, not directly on K.

03 · GRAPH COLORING

What does a color mean?

Each graph node is a virtual register. Edges represent interference. Assigning the same color to connected nodes would be invalid; each color corresponds to a physical register.

04 · MEMORY SPILLING

What if K is too small?

The compiler rewrites chosen values using stack spill slots, then rebuilds the graph. A conservative fallback can make difficult cases work at the expense of extra memory traffic.

Supported TAC syntax

func main
  t1 = 5               # constant
  t2 = t1              # copy
  t3 = t1 + t2         # arithmetic
  if t3 < 10 goto L1  # conditional branch
  goto L2              # unconditional branch
label L1
  t4 = t3 * 2
label L2
  ret t3
end

Use register names t1, t2, etc. Operators include + - * / % and relations < <= > >= == !=. Only one function is supported. Spill loads and stores are inserted internally.

Scope and verification

This is a teaching implementation of intra-procedural graph-coloring register allocation. Its reference interpreter compares the return value of the original TAC and spill-rewritten TAC where execution is bounded and supported. It does not emit machine code or verify machine execution. Results from the Complexity lab describe the Python allocator, not the runtime of compiled binaries.
